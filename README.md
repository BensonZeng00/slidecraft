# 幻灯匠 / Slidecraft

**先设计，再制作：让 PPT 不止于套模板，更不用开盲盒。**

有了内容，却找不到合适的模板；AI 生成的图片很好看，想改一句话、挪一个位置，却又得重新来过。

幻灯匠让内容决定画面：先根据提示词、受众、用途和参考图判断视觉风格，告诉你选择及理由，再生成完整的信息图，**你看过、确认满意后，再制作可编辑 PPT**。不必等整页做完才发现风格不对。也可以上传喜欢的信息图，直接指定它作为复刻目标。

**两步完成：① 看设计图，确认或修改；② 复刻 PPT，检查后交付。** 单页同样先确认，不自动越过这一步。

不用先挑模板，也不用自己从空白页逐个摆放元素。它增强你已有的 PPT 工具，让个性化构图、插画与后续编辑衔接起来。

## 它能帮你做什么

- **从想法到页面**：输入主题，生成信息图，再制作可编辑 PPT，减少手工排版。
- **出图前说明风格**：优先遵循你指定的风格和品牌要求；未指定时结合内容与使用场景判断，提前说明配色、信息层次和插画方向，不靠主题关键词套模板。
- **让参考图继续可用**：重建已有图片或 SVG，方便改文案、调布局、复用内容。
- **减少整套返工**：多页先讨论大纲和每页内容，你确认后再逐页制作，每页满意再继续。
- **控制重复生成**：提前说明生图数量，默认每页最多 3 次调用，成功即停止，达到上限就暂停。
- **减少机械返工**：优先复用 CLI 做版本、确认记录、文字尺寸和交付检查；生图仍有随机性，不承诺像素级一致。

推荐从单页开始：一条提示词，专注做好一页。

## 安装：从 GitHub 开始

项目地址：[BensonZeng00/slidecraft](https://github.com/BensonZeng00/slidecraft)。推荐在支持自定义 Skill、能够访问 GitHub 的 AI 助手中，直接发送：

```text
安装技能：https://github.com/BensonZeng00/slidecraft
```

幻灯匠需配合平台已有的生图、可编辑 PPT 制作和渲染工具使用，不自带生图模型或 PPT 引擎。

### 手动安装（可选）

如果助手无法直接访问仓库，可以选择以下一种方式：

- **下载 ZIP**：[下载 main 分支技能包](https://github.com/BensonZeng00/slidecraft/archive/refs/heads/main.zip)。解压后将 `slidecraft-main` 文件夹改名为 `slidecraft`，按平台要求导入或放入技能目录；如果平台要求上传 ZIP，按其要求重新打包。
- **使用 Git**：在当前平台支持的技能父目录中运行下列命令。技能目录的位置以该平台说明为准。

```bash
git clone https://github.com/BensonZeng00/slidecraft.git
```

安装后的目录结构应为 `slidecraft/SKILL.md`，并保留 `references/`、`scripts/` 等配套文件，不要只复制入口文件。按平台提示刷新技能列表或重新开启会话，再选择 `slidecraft`，也可以在请求中明确写“使用幻灯匠”。

后续更新：Git 安装可在 `slidecraft` 目录运行 `git pull --ff-only`；ZIP 安装可重新下载导入。如有本地修改，先备份并处理差异。

## 使用：先做一页，走通完整流程

### 1. 描述你要做的页面

选择幻灯匠技能后，说明**主题、给谁看、页数和必须保留的内容**；有喜欢的风格或参考图，也可以一起提供。无需先写一份设计说明，下面这段就能开始：

```text
使用幻灯匠，制作一页“人工智能发展简史”，面向非技术听众。
采用清晰、简洁的时间线风格，突出关键里程碑。
先生成设计图让我确认，确认后再制作可编辑 PPT。
```

### 2. 看设计图，确认或提出修改

生成前，助手会先简短说明采用什么风格、为什么适合你的内容，以及具体视觉特征。例如：

> 根据你提到的“面向非技术听众”和发展简史主题，我会采用清晰的科普时间线风格：浅色背景、醒目的年份层级，配合简洁的示意插画，帮助读者快速理解各阶段变化。

这一步默认是告知，不额外等待确认；只有关键要求存在冲突或你明确要求先确认风格时才暂停。选定方向会写入生图提示词，多页沿用统一风格，修改风格时也会在重新生成前说明。

随后助手展示设计图，等待你的反馈。需要调整时，直接指出哪里要改，例如“标题再大一点，时间线保留 5 个节点，背景改为浅色”。修改后会再次展示，满意再回复：

```text
确认这版设计，请按这张图制作可编辑 PPT。
```

**确认的是当前这版设计。** 设计发生变化后需要重新确认；单页也遵循这个步骤，避免 PPT 做完才发现“不是我想要的那味儿”。

### 3. 检查 PPT 预览，拿到文件

确认设计后，助手制作可编辑 PPT，检查实际渲染结果，再提供 `.pptx` 和预览。你可以根据预览继续提出具体修改，例如“右侧说明文字放大，保持三列布局”，检查满意后下载使用。

### 已有图片或 SVG：直接指定复刻目标

上传文件后发送：

```text
使用幻灯匠，把附件中的这张信息图作为已选定的复刻目标，重建为一页可编辑 PPT。
尽量保留原图布局、文字、比例和风格，并提供实际 PPT 预览。
```

明确指定的附件可以直接进入制作；如果要先改设计，说明修改要求，等新设计确认后再制作。

### 制作多页：先定大纲，再逐页确认

```text
使用幻灯匠，制作一套 6 页的产品方案介绍，面向潜在客户。
内容包括客户问题、产品定位、核心功能、使用场景、实施计划和下一步行动。
先和我讨论大纲及每页内容，确认后逐页制作。
每页先确认设计图，再制作 PPT 并让我确认成品，之后继续下一页。
```

完整顺序：**确认大纲与每页内容 → 确认当前页设计图 → 制作并确认当前页 PPT → 下一页 → 汇总交付。** 大纲确认不代替页面确认；当前页未确认，不制作下一页。

## 最后会得到什么

一份可编辑的 `.pptx` 和实际 PPT 预览；文字生图流程还会提供生成的参考图。多页在全部确认后交付一份完整文件。

文字、基础图形和简单关系优先使用原生 PPT 对象。照片、复杂插画和纹理可能保留为独立图片，可移动或替换，但内部细节不能逐项编辑。不会把整页截图贴进 PPT 就宣称“全部可编辑”。

## 当前状态

当前版本：`0.4.0-beta.8`（Beta）。

复刻默认忠实保留已选原图的全部文字、布局、连线走向、背景、装饰和插画细节。原图即使看起来有错误，也只在工作记录中提示，不擅自纠错或重设计；只有用户明确指定的改动才进入制作。确认设计不等于批准助手自行提出的修改。

CLI 新增 `workflow.py fidelity-check`，制作门禁同时检查冻结的原图元素清单与复刻计划。交付检查新增必需参数 `--state`，要求绑定原图与最终渲染的对照记录。旧项目需补做原图清点和实际对照，不能把过去的“看起来不错”视为保真验证。详见[保真约定](references/fidelity-contract.md)。这些检查能拦截记录中的未授权差异，不能自动理解图片或保证像素级一致。

按阶段加载说明：设计阶段只读设计与确认规则，你确认后再加载 PPT 制作和验收文档。CLI 检查和确认门禁保留，不为节省上下文而省略质量检查。

已有 Codex Windows 单页生图、重建与渲染记录，以及 PowerPoint 16.0 改字、移动节点和保存重开记录。新版设计确认门禁与文字预检有 CLI 回归测试；新版真实用户两步确认、完整多页流程及其他平台仍待实测。不承诺所有平台通用或像素级还原。

测试记录：[TEST-REPORT.md](TEST-REPORT.md)。调用预算与恢复规则：[项目进度说明](references/project-state.md)。
